Detailed Description

Binary-search word->phoneme dictionary backed by four flat, flash-resident arrays.

Replaces the old PhonemeEntry{const char* word, const char* phonemes} table (two pointers per entry, plus a separately-stored, null-terminated ASCII string for every word AND every phoneme sequence) with:

  • wordOffsets[count+1]: cumulative offsets into wordsBlob
  • wordsBlob: every word's bytes concatenated, no separators/terminators (word i's length is wordOffsets[i+1]-wordOffsets[i])
  • phonemeOffsets[count+1]: cumulative offsets into phonemeData
  • phonemeData: one byte per phoneme, packed as (phoneme_id << 2) | stress, where phoneme_id indexes Phonemes::getPhonemeById() (see the Phone enum in Phonemes.h) and stress is 0 (none), 1 (primary) or 2 (secondary) – decoded back into a space-separated ARPABET string, e.g. "HH AH0 L OW1".

This drops both the two-pointers-per-entry overhead and the ASCII-text cost of storing phonemes as multi-character tokens with spaces and a null terminator (1 byte per phoneme here vs. 3-4+ ASCII bytes). All four arrays are position-independent (offsets only, never pointers into each other), so they can be built by hand, generated by a script (see setup/dictionary for the full CMU-dictionary port), or – for hand-maintained tables – produced at COMPILE TIME from a readable {"word", "PHONEMES"} source table via CompactPhonemeDictionaryBuilder.h, so no separate build step is needed to keep them in sync.

Entries must be sorted by word (binary search), exactly like the old PhonemeEntry tables.

Note
Memory footprint: ~8 bytes/word of pure index overhead (two 4-byte cumulative offsets), plus 1 byte/phoneme and the raw word text – e.g. the built-in 535-word default dictionary measures ~10KB total. For larger (>10k word) dictionaries, prefer CompressedPhonemeDictionary, which trades some CPU per lookup for a smaller flash footprint. See https://github.com/pschatzmann/TinyTTSTools/blob/main/docs/MEMORY.md for a comparison table across all vocoders and G2P models.
