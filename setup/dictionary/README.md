# Dictionary generation pipeline

Regenerates the two big compact/compressed phoneme dictionaries
(`CompactCmuDictionaryEN_data.h`, `PhonemeExceptionDictionaryEN_data.h`) and
their shared Huffman code table (`PhonemeHuffmanCodes.h`).

The small, hand-maintained ~500-word default dictionary
(`src/TinyTTSTools/PhonemeDictionary/PhonemeDictionaryEN.h`) is unrelated to this
pipeline -- it's a readable `PH_WORD(...)` source table compiled at build
time via `CompactPhonemeDictionaryBuilder.h`, not generated by a script.

## Pipeline order

1. **`cmudict_dump.txt`** -- `word<TAB>PHONEMES` (with stress digits), one
   per line, for all ~123k CMU dictionary words. Regenerate from the
   currently-shipped data with `dump_cmudict.cpp`:
   ```
   g++ -std=c++17 -O2 -I ../../src dump_cmudict.cpp -o /tmp/dump_cmudict
   /tmp/dump_cmudict > cmudict_dump.txt
   ```
2. **`failures.txt`** -- every CMU word (stress-stripped) where
   `G2PRuleBasedModel`'s letter-to-sound rules get the pronunciation wrong.
   This is the exception dictionary's source list -- if you improve the
   rules in `G2PRuleBasedModel.h`, regenerate this to shrink the exception
   set. Requires `cmudict_dump.txt` above:
   ```
   g++ -std=c++17 -O2 -I ../../src dump_failures.cpp -o /tmp/dump_failures
   /tmp/dump_failures > failures.txt
   ```
3. **`python3 build_huffman.py`** -- reads both `.txt` dumps, computes real
   packed-phoneme-byte frequencies across the combined corpus, and emits
   `src/TinyTTSTools/PhonemeDictionary/PhonemeHuffmanCodes.h` (a readable
   `{packedByte, code, length}` table, canonical Huffman order).
4. **`python3 regen_cmudict.py`** / **`python3 regen_exceptions.py`** --
   pack `cmudict_dump.txt` / `failures.txt` into the
   `CompressedPhonemeDictionary` binary format (blocked word-offset index +
   Huffman-coded phoneme bitstream -- see
   `src/TinyTTSTools/PhonemeDictionary/CompressedPhonemeDictionary.h`) using the
   codes from step 3, overwriting the two `*_data.h` headers.

Steps 3 and 4 must be re-run together whenever the corpus changes (adding/
removing words, or improving the rules and shrinking `failures.txt`) --
`regen_cmudict.py`/`regen_exceptions.py` always encode with whatever codes
`build_huffman.py` last computed, so a stale Huffman table would still
*decode* correctly (each dictionary is self-consistent) but wastes the
compression opportunity a fresh frequency count would find.

## Verifying a regeneration

There's no automated test target for this (yet) -- after regenerating,
build a small program against the new header and compare every entry's
`lookup()` result back against the `.txt` dump it came from; a full
123k-word round-trip check compiles and runs in a couple of seconds. Also
worth re-running the `G2PDictionaryAndRulesModel` +
`getDictionaryModel().useCompactDictionary(PHONEME_EXCEPTION_DICTIONARY_EN)`
check against `cmudict_dump.txt` to confirm the rules+exceptions
combination still covers the whole corpus.

## Files

- `pack_common.py` -- the `Phone` enum <-> packed-byte mapping, and
  `.txt` dump loading/deduplication, shared by everything else here.
- `build_huffman.py` -- canonical Huffman code computation +
  `PhonemeHuffmanCodes.h` emission.
- `pack_compressed.py` -- packs an entry list into
  `CompressedPhonemeDictionary`'s six backing arrays + emits a `*_data.h`.
- `regen_cmudict.py`, `regen_exceptions.py` -- thin drivers tying the above
  to the two specific big dictionaries.
- `dump_cmudict.cpp`, `dump_failures.cpp` -- C++ tools producing the two
  `.txt` dumps from the currently-shipped (or a freshly-rebuilt) library.
