98 // No synthesizePhoneme() override here (deliberately): a previous version
99 // treated its whole `phoneme` argument as ONE literal dictionary key,
100 // which only worked because every caller used to pass exactly one
101 // phoneme per call. Once TinyTTSTools::sayPhonemes() was fixed to pass a
102 // whole multi-phoneme utterance in a single call (so DiphoneVocoder could
103 // form real diphones), that assumption broke: dictionary_.getSoundEntry()
104 // was asked to look up e.g. "DH AH SP K W IH K" as a single name, which
105 // never matches anything, so every multi-token utterance silently
106 // produced zero audio. ConcatenatedAudioVocoder's own synthesizePhoneme()
107 // already does the right thing generically -- splits the sequence,
108 // handles SIL/SP, provides next-unit lookahead for cross-fade, and
109 // flushes the batch at the end (the old override never did any of the
110 // last three, even for a single phoneme) -- so inheriting it is strictly
111 // better, not just simpler.
